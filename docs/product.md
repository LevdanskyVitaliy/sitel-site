# Продукт и структура сайта

## 1. Позиционирование

**Позиционирование итерации 2 (актуальное, источник — драфт презентации):** Sitel — **платформа комплексной ИИ-тизации бизнес-задач** («all-in-one»), а не отдельный продукт речевой аналитики. Продаём ядро — векторную БД, ASR, NLU, голосовую биометрию, no-code конструктор бота и Аналитику v2.0, — на котором собираются отраслевые решения: речевая аналитика, умный автозаказ, документооборот, корпоративные ИИ-ассистенты.

Опорные цифры из драфта (маркированы как заявления продукта, подтверждаются пилотом): 95% точность транскрибации (ASR), ≥90% точность распознавания интентов (NLU), отклик < 1 сек, автоматизация 60–80% рутинных вызовов голосовым ботом, 0 ₽ капитальных затрат на GPU (базовые сервисы — на CPU; для расширенной аналитики достаточно одной розничной RTX 4090), 100% работа в закрытом контуре по 152-ФЗ.

Итерация 2 сохраняет прежний фундамент: Sitel продаёт **речевую аналитику с суверенитетом данных** для контакт-центров, ритейла, банков и медицины (РФ). Ключевое обещание: базовый продукт работает у клиента навсегда, на его сервере, без счётчиков минут и зависимости от вендора и интернета. Расширенный «интеллект» подключается опционально. Метафора из питч-документа: базовый продукт — автомобиль в собственности, подключаемый интеллект — нанятый штурман.

Целевая метрика доверия: «даже если завтра отключат интернет и закончится подписка — вот что продолжит работать у вас».

## 2. Двухуровневая продуктовая модель

### Уровень 1 — «у вас навсегда» (базовый продукт)
Работает на **обычном сервере заказчика + одна розничная видеокарта класса RTX 4090 (24 ГБ)**. Распознавание речи идёт на CPU — это ядро технологического отличия. GPU нужна только для малой языковой модели. Входит:
- Расшифровка 100% звонков, поиск по всем разговорам;
- Контроль скриптов и запрещённых фраз (комплаенс), каждое правило — да/нет с цитатой;
- Объективные метрики (перебивания, паузы, доля речи), эмоции по голосу, темы обращений;
- Базовый скоринг операторов и выявление проблемных звонков/операторов;
- Дашборды, отчёты, выгрузки, уведомления;
- Малая языковая модель на GPU клиента: краткое резюме звонка, автонейминг тем, простые смысловые проверки.

Принципиально: **хранение данных — только у клиента**. Аудио и тексты не покидают контур никогда.

### Уровень 2 — «по подключению» (расширенный интеллект)
Большие языковые модели — к общему серверу компании Sitel (контур Б), нашему сервису по подписке или арендованной машине:
- Глубокая оценка операторов по смыслу (чек-лист с цитатами, развёрнутое резюме);
- Автоматические выводы и дайджесты, самообучение бота;
- Совпадение с оценками супервизоров — целевое ≥85–90% (подтверждается пилотом).

Уровень 1 работает без Уровня 2. Вердикты Уровня 2 «дозаполняются» задним числом в хранилище клиента при подключении — ничего не теряется.

## 3. Три формы подключения (контуры)

| Контур | Что это | Для кого |
|---|---|---|
| **А** | Свой GPU-сервер внутри компании | Банки, телеком, госсектор — данные не покидают периметр |
| **Б** | Сервис Sitel по подписке | Обезличенные тексты (ПДн вырезаются до отправки), оценки обратно; аудио не передаётся никогда |
| **В** | Аренда машины на ночь | Машина поднимается на 1–2 часа, обрабатывает очередь (10 000 звонков за ночь) и гасится |

На сайте контуры описаны на `index.html` и подробно на `architecture.html`.

## 4. Три слоя хранения (заявлено на architecture.html)

- **Слой A — конвейер**: словари/правила (CPU) → эмоции (CPU/GPU) → акустика (CPU) → эмбеддинги (GPU ускоряет) → малая модель (розничная GPU). Реализация старт: Postgres + pgvector.
- **Слой B — витрина звонков**: канонизированный текст, темы, эмоции, объективные метрики, отметки скрипта, векторные представления, вердикты Уровня 2 (дозаписываются по мере возврата).
- **Слой C — витрины-агрегаты**: агрегаты по оператору/команде/теме/периоду; обновляются инкрементально при записи звонка, фоновой пересчёт — только при смене правил. Дашборды читают только слой C. Миграционный путь роста: ClickHouse.

## 5. Три платформы в меню «Платформы»

| Платформа | Страница | Статус |
|---|---|---|
| Речевая аналитика | `index.html` | Главная-хаб платформы: hero про all-in-one, таблица «гибрид vs чистые LLM», ядро из 6 компонентов, блок «Плюшки для бизнеса» |
| Умный автозаказ | `platforms/auto-order.html` | Предиктивный автозаказ для ритейла: почему ручной теряет деньги, как работает предиктив, что получают клиенты |
| Документооборот | `platforms/docs.html` | «Четыре задачи — одно решение», архитектура платформы на векторной БД и RAG |

В навигации пункт меню называется просто «Речевая аналитика» — без пометки «флагман», чтобы не сужать позиционирование платформы до одной задачи (правило итерации 2).

## 7. Аудитория и тон

Решение о покупке принимает enterprise-заказчик (ИБ, ИТ, руководитель контакт-центра). После итерации 2 аудитория шире: руководитель операционного блока, ИТ-директор и владелец процессов (документооборот, совещания, автозаказ). Тон сайта: сдержанный, доказательный, без маркетингового перегрева; недоказанное маркируется плейсхолдерами, есть секция «Что мы не обещаем» — это сознательное правило ревью (см. rules-and-status.md).
